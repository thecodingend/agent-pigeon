## Design Context

### Users
Agent Pigeon is a desktop web app for building and operating email-native AI agents. Each agent is given a real email address and lives inside real inboxes, so the product's job is to make agents easy to configure, route, and observe — then get out of the way so the actual work happens over email.

The audience is mixed. Founders and operations leads sit side-by-side with developers and power users, often inside the same team. The interface must feel approachable on the surface so a non-engineer can confidently spin up an agent, while revealing real depth on demand for the people wiring tools, prompts, and routing rules. The product is currently desktop-first; mobile is out of scope for this phase.

### Brand Personality
The brand should feel calm, deliberate, and quietly capable, with a small streak of character so the product is not boring.

Emotionally, the interface should feel inhabitable rather than chore-like. Configuring an agent is a thoughtful act, not a form to plough through, and the UI should respect that. The pigeon thread — message-carrying, dependable, a little charming — can show up in copy, empty states, and small details, but never as decoration or cartoon. Power users should feel respected, ops leads should feel oriented, and nobody should feel the product is talking down to them.

### Aesthetic Direction
The visual direction is light mode only, anchored on a pure white background with near-black text and Airbnb's signature red (Rausch, `#FF385C`) as the single brand accent. Reference energy is Linear and Superhuman: hairline structure, generous whitespace, decisive typography, and meta information set in monospace. The Superhuman reference is about feel and density, not metaphor — this is an agent configuration product, not an email client, so do not borrow inbox-list patterns by default.

Typography pairs Mona Sans Variable for display and body with Geist Mono Variable for IDs, agent email addresses, timestamps, environment values, and anything that is machine-shaped. Sections, panels, and groups are separated by a single 1px border at 10% black opacity, with structure carried by typography and rhythm rather than cards-inside-cards or heavy chrome. Color is restrained: white surfaces, near-black text, neutrals tinted faintly toward the brand red for cohesion, and the red itself reserved for primary actions and identity moments rather than sprinkled for decoration.

This should explicitly not look like a generic AI SaaS (no purple-to-blue gradients, no neon glow on dark, no sparkle icons) and not like an enterprise CRM (no dense toolbars, no blue-everywhere palette, no Salesforce-style chrome). It should also not look like a default shadcn or Vercel template, which means moving off Geist as the primary face and off the stock zinc neutral.

### Design Principles
1. Approachable on the surface, deep on demand: the front door must read clear and uncrowded for non-engineers, with configuration density unfolding progressively for power users.
2. Configure, then get out of the way: dashboard screens are a workspace people pass through to set agents up, not a place to live; the product belongs in the inbox.
3. Carry structure with hairlines and type, not chrome: a single 1px black-at-10% border and a strong typographic hierarchy do the work of cards, shadows, and dividers.
4. Mix proportional and monospace with intent: Mona Sans for product voice and content, Geist Mono for agent addresses, IDs, timestamps, and any machine-shaped value the user needs to read or copy.
5. Earn character through small, confident moves: a single brand accent, a well-placed pigeon reference in copy or an empty state, and restrained micro-detail beat badges, gradients, mascots, and decoration.
